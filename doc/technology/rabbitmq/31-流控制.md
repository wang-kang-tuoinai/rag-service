# 流控制

## 概述

本指南介绍了 RabbitMQ 节点应用于发布连接的一种背压（back pressure）机制，旨在避免内存使用量失控增长。这是必要的，因为节点中的某些组件可能比发布客户端执行的工作量大得多（例如，将数据复制到 N 个对等节点或将其存储到磁盘上），从而导致其处理速度跟不上快速的发布者。

## 流控是如何工作的

如果连接的发布速度过快，导致队列无法及时处理，RabbitMQ 将降低该连接的速度。无需任何配置。

处于流控状态的连接会在 `rabbitmqctl`、管理界面以及 HTTP API 响应中显示为 `flow` 状态。这意味着连接正在以每秒多次的频率进行阻塞和解除阻塞，以保持消息的进入速率在服务器其余部分（例如消息路由到的队列）所能处理的范围内。

通常情况下，处于流控状态的连接与正常运行时没有任何区别；显示 `flow` 状态是为了通知系统管理员发布速率受到了限制，但从客户端的角度来看，这看起来就像是到服务器的网络带宽低于实际带宽一样。

除了连接外，其他组件也可能处于 `flow` 状态。通道（Channels）、队列以及系统的其他部分都可以应用流控，并最终传播回发布连接。

若要查明消费者和预取设置（prefetch settings）是否是关键限制因素，请查看相关指标。详情请参阅监控与健康检查指南。
