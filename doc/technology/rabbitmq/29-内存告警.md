# 内存报警阈值

## 概述

本指南涵盖了 RabbitMQ 内存阈值（水印）设置。此外还有一些相关指南供参考

  * 内存使用原理
  * 监控
  * 资源告警



## 内存阈值：定义与工作原理

可以为 RabbitMQ 节点提供内存占用限制提示。如果节点的内存占用超过该值，将在当前节点（最终在所有集群节点）上触发资源报警，从而阻塞发布者。

该限制可以配置为绝对值或相对值。若是相对值，RabbitMQ 将在启动时以及执行 `rabbitmqctl set_vm_memory_high_watermark _value_` 命令时，尝试检测其可用的总内存量。

默认情况下（包括未配置限制提示时），RabbitMQ 节点将使用约 60% 的可用内存；一旦超过该比例，它会触发内存报警并阻塞所有发布消息的连接。一旦内存报警解除（例如，通过将部分消息交付给消费者并收到确认），正常服务将恢复。

警告

该限制并不能阻止 RabbitMQ 节点使用超过计算限制的内存，它仅仅是阻塞发布者的临界点。

## 配置内存限制（或阈值）

### 绝对内存限制

提示

强烈建议在 Kubernetes 等容器化环境中使用绝对内存阈值。RabbitMQ 节点并不总能准确检测到有效的 cgroups 限制。

可以通过设置节点使用的 RAM 绝对限制来调整内存阈值。以下示例将阈值设置为 1073741824 字节（1024 MiB）。
    
    
    vm_memory_high_watermark.absolute = 1073741824  
    

相同示例，但使用了内存单位。
    
    
    vm_memory_high_watermark.absolute = 1024MiB  
    
    
    
    vm_memory_high_watermark.absolute = 4Gi  
    
    
    
    vm_memory_high_watermark.absolute = 1Ti  
    

支持的十进制（十的幂）内存信息单位包括：

  * `GB` 表示 千兆字节 (1000^3 或 10^9 字节)
  * `MB` 表示 兆字节 (1000^2)
  * `TB` 表示 太字节 (1000^4)
  * `PB` 表示 拍字节



支持的二进制（二的幂）内存信息单位包括：

  * `Gi` 表示 吉比字节 (1024^3 或 2^30 字节)
  * `Mi` 表示 兆比字节 (1024^2)
  * `Ti` 表示 太比字节 (1024^4)
  * `Pi` 表示 拍比字节



同时也支持 Kubernetes 样式的单位

  * `Gi` 表示 吉比字节 (1024^3 或 2^30 字节)
  * `Mi` 表示 兆比字节
  * `Ti` 表示 太比字节
  * `Pi` 表示 拍比字节



如果设置的绝对限制大于已安装的 RAM 或可用的虚拟地址空间，则阈值将取两者中的较小值。

RabbitMQ 节点启动时，内存限制会附加到 日志文件中。
    
    
    2023-06-10 23:17:05.976 [info] <0.308.0> Memory high watermark set to 1024 MiB (1073741824 bytes) of 8192 MiB (8589934592 bytes) total  
    

内存限制也可以通过 `rabbitmq-diagnostics memory_breakdown` 和 `rabbitmq-diagnostics status` 命令进行查询。

### 相对内存阈值

警告

不建议在 Kubernetes 等容器化环境中使用相对内存阈值。请优先使用 绝对阈值。

可以通过编辑 配置文件来调整触发流控的内存阈值。

以下示例将阈值设置为默认值 0.6。
    
    
    vm_memory_high_watermark.relative = 0.6  
    

默认值 0.6 代表可用（检测到）RAM 的 60%。

### 在运行中的节点上更新内存阈值

可以在 Broker 运行时通过以下方式更改阈值：
    
    
    rabbitmqctl set_vm_memory_high_watermark <fraction>  
    

命令或
    
    
    rabbitmqctl set_vm_memory_high_watermark absolute <em><memory_limit></em>  
    

例如：
    
    
    rabbitmqctl set_vm_memory_high_watermark 0.7  
    

和
    
    
    rabbitmqctl set_vm_memory_high_watermark absolute "4G"  
    

有关支持的内存信息单位，请参阅 绝对阈值。

这两个命令的效果仅持续到节点停止。若要使设置在节点重启后依然有效，请使用配置文件设置。

在支持热插拔 RAM 的系统上，如果执行此命令时不更改阈值，内存限制可能会发生变化，因为系统会重新查询总 RAM 量。

运行时的内存分配设置会影响节点的内存占用。此主题在 运行时指南中有介绍。

## 在容器和 Kubernetes 上运行 RabbitMQ

提示

Kubernetes 版 RabbitMQ 集群操作器会自动配置内存限制。使用操作器是在 Kubernetes 上运行 RabbitMQ 的推荐方式。

当 RabbitMQ 节点在容器中运行时，其检测可用内存量的能力取决于外部因素：所使用的运行时版本、镜像使用的操作系统版本及设置、cgroups 版本，以及最终的 Kubernetes 版本。

这意味着在容器化环境中，最佳方案是配置绝对内存限制。

另一个 Kubernetes 特有的内存占用方面是操作系统管理的内核页面缓存，特别是在使用流（Streams）和超级流（Super Streams）的集群中。

## 如何临时停止所有发布

当阈值或绝对限制设置为 `0` 时，内存报警会立即触发，从而最终阻塞所有发布连接。如果您希望全局停用发布功能，这会非常有用。
    
    
    rabbitmqctl set_vm_memory_high_watermark 0  
    

## 有限的地址空间

危险

RabbitMQ 仅支持 64 位操作系统和 64 位 Erlang 运行时。

当在 64 位操作系统（或带有 PAE 的 32 位系统）内的 32 位 Erlang VM 中运行 RabbitMQ 时，可寻址内存是有限的。服务器将检测到这一点并记录类似以下的消息：
    
    
    2018-11-22 10:44:33.654 [warning] Only 2048MB of 12037MB memory usable due to limited address space.  
    

## 无法识别的平台

如果 RabbitMQ 服务器无法检测其运行的操作系统，它将在 日志文件中添加警告。此时它会默认已安装 1GB RAM。
    
    
    2018-11-22 10:44:33.654 [warning] Unknown total memory size for your OS {unix,magic_homegrown_os}. Assuming memory size is 1024MB.  
    

在这种情况下，请将 `total_memory_available_override_value` 设置为系统中实际可用的内存量。`vm_memory_high_watermark.relative` 将会基于 `total_memory_available_override_value` 中设置的值进行计算。

有关建议的 RAM 水印设置指南，请参阅 部署指南。
